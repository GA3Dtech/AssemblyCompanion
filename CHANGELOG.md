# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
`package.xml`.

## [Unreleased]

### Changed
- Icons: "Insert component (visual)" shows the explorer folder with a part
  coming out of it; "Open source file" (a page with an open arrow) no longer
  looks like "Archive"; icons on the "New part…" and "Shape for TechDraw"
  buttons of the selection sets.
- New part / new file / extract: the prefix is the one of the working
  folder (from its part files, else from its name, e.g. GI_MiniEtau -> GI)
  and changes only with the folder.
- New part from selection: the view of the new part is fitted (as V, F).

### Notes
- FreeCAD regression upstream (FreeCAD/FreeCAD#34357, Blocker, milestone
  27.1): since commit 24ea8589a FreeCAD saves links to other files with
  absolute paths, so a copied or moved project points back to the original
  files. It explains every failure of the weekly build in our CI, and it
  was reported as backported to the 26.3 branch after RC2. New test
  `test_link_resolution.py` checks that the links of a copied project
  resolve to the copy (passes on 1.1 and 26.3rc; prints the FreeCAD version
  and the stored paths when it fails). Advice: check this test before
  moving to a new FreeCAD version, and keep backups of multi-file projects.
  Checked locally on weekly-2026.11.25 (27.1.0 dev): 8 failures, all from
  this regression (stored link path absolute), the other 58 tests pass.

### Changed
- CI: the 26.3 job resolves at each run to the 26.3 stable release as soon
  as it is published (its newest release candidate until then).

### Fixed
- Freeze: a Body holding only a SubShapeBinder (as made by "New part from
  selection") became invisible once frozen: such a Body has no shape of its
  own; the frozen copy now holds what it shows (its visible members). In
  "one block" mode such a part stops the freeze with a clear message
  instead of being left out silently.
- Explorer: tagging a folder or adding it to the favorites rebuilt the whole
  view (slow on a large library): only that folder's block is rebuilt now.

### Added
- New file: a new, empty part file named like the new parts (prefix, next
  free number, revision, description), by default with a Std_Part container
  holding an empty Body named after the description (names editable,
  container and Body optional). API `new_file`.
- Explorer: tags are searchable (the filter matches the #tag or emoji of
  files and folders).
- Preferences: save / restore the favorites, tags and library folder of the
  explorer to a JSON file (merged on restore). They live in the preferences
  of one FreeCAD version, not in the thumbnail cache: emptying the cache
  keeps them, a new FreeCAD version starts without them.

## [0.2.0] - 2026-11-24

### Added
- Tooling: ruff and pytest configuration (`pyproject.toml`), pre-commit hooks,
  `.gitattributes`, this changelog.
- Test fixtures generator (`tests/fixtures/build_fixtures.py`) and frozen
  legacy files of version 0.1.0 (`tests/fixtures/legacy/v0.1.0`).

- Unit tests (`tests/unit`, pure Python, FreeCAD stand-ins when absent):
  subnames, file naming, revisions, CSV, preferences, translations,
  package.xml.

- Public API `api.py` (+ `errors.py`) for scripts, macros and other addons;
  reference `docs/api.md` generated by `tools/api_doc.py` (checked in CI);
  README section "Python API". The Freeze, Relink and BOM commands
  go through the API.
- FreeCAD integration tests (`tests/freecad`) and compatibility tests with a
  FreeCAD without any addon and with the 0.1.0 code (`tests/vanilla`).

- GUI smoke tests (`tests/gui`) and a GitHub Actions CI running every level
  with FreeCAD 1.1.4, 26.3rc2 and the latest weekly build (allowed to fail);
  failures are reported as annotations.

- Explorer and visual insertion: targeted refresh. Right-click a folder
  header to refresh only that folder (or its subtree); documents saved from
  FreeCAD under the library refresh their own folder; "Refresh all" and every
  refresh rebuild only the folders that changed (scroll and filter kept).
  New preference "Full library scan" (every opening / once per session /
  only on demand, default once per session). Scan logic in `library.py`; `api.scan_library` and
  `api.list_library`; benchmark `tools/bench_library.py`.

- Generic panels: a panel is described once as a model (`panel_model.py`)
  and shown either in QML (`bridge.py`, `qml_host.py`, `resources/qml/`) or,
  without Qt Quick, with classic widgets built from the same model.
  Preference "Use the QML panels". `tools/i18n.py` also scans the `.qml`
  files. Panels migrated: "Frozen parts up to date?", "New part from
  selection" (now created through the API), "Check collisions" results
  (modeless, a click on a row selects the two parts).

- Explorer cache: its size and location on the preference page, with an
  "Empty the cache" button; changing the parts library folder offers to
  delete the cache of the previous folder. The cache folder can be chosen
  (systems that empty their cache folder daily): changing it offers to move
  the existing cache or to start empty; the folder is private to the user.

- Freeze: sub-assemblies (App::Link to an assembly and Assembly::AssemblyLink
  of FreeCAD 26.x, several levels) and imported STEP groups (App::LinkGroup)
  are frozen with their parts, names, placements, colours and internal
  joints; option "one solid per component" (preference, API mode="block");
  relink, refreeze, BOM and diagnostic follow. Nothing is half frozen: a
  component that cannot be frozen stays linked and is reported, and any
  error undoes the whole freeze.

- Explorer favorites and tags: right-click a folder to add it to the
  favorites (pinned on top, ★ menu, "Favorites only" filter, missing
  folders reported); emoji or short #tag shown on a card or a folder
  header; stored in the user preferences (button to clear them).
- Extract bodies: each selected Body goes with its whole tree to its own new
  file (new-part naming), binders detached, outside attachments removed,
  report of what still points outside; option to replace the bodies in the
  assembly by the new parts (joints kept). API `extract_bodies` (dry_run).
- Import STEP as part: the import groups of the STEP importer (App::LinkGroup)
  become Std_Parts, so every element is visible and usable for joints in
  the assembly; the Part is saved in a new FreeCAD file next to the assembly
  (default) or created in the assembly document, then inserted. The user's
  STEP import settings are used. Also from the explorer, which now lists
  STEP files (click / right-click to insert). API `import_step`.
- BOM by sub-assembly: preference "Bill of materials by sub-assembly" and
  `api.bom(doc, hierarchical=True)` / `export_bom_csv(..., hierarchical=True)`
  (sub-assemblies as rows holding their parts, "Level" column in the CSV).

### Fixed
- Freeze: a frozen sub-assembly could be rearranged (parts stacked) when its
  source placements did not satisfy its joints: the joints are now copied
  without pre-solve / solve and every frozen part keeps its source placement.
- Explorer: the question about deleting the cache of the previous library
  folder could appear during a refresh (old folder taken from PiStock's
  setting); it is now asked only when the user changes the folder.
- Freeze: a sub-assembly lost all its parts (only Bodies and solids were
  copied into the frozen container), and the parts of an imported STEP
  group disappeared.
- BOM and freeze: a Link of another file carrying the name of a sibling
  could hide that sibling (names were compared without their document).
- Preferences: the "Assembly Companion" page could show the settings of
  another addon (CroquisFreeCAD): FreeCAD keys Python pages by class name,
  ours is now `AssemblyCompanionPreferencePage`.
- Explorer: folders open again in the file manager with a FreeCAD AppImage
  (its PYTHONHOME was inherited and made Nemo fail): the file manager is
  started without the bundle's variables.
- Lightweight components: restoring finds the source file next to the
  assembly when the project folder was moved or copied to another computer
  (only the stored absolute path was tried).
- Diagnostic: a reference to an element that does not exist (e.g. `Face999`)
  is reported broken.

### Changed
- README: status table (stable / experimental) per function, credits table
  (PiStock, ShowRoom, FreeCAD-Nxt), release process (`docs/RELEASING.md`).
  Every source file carries the SPDX line and the LGPL header (checked).
- Toolbar and menu ordered by workflow (library first; fasteners,
  alignment and reactivation last), one toolbar with separators.
- Passive workbench: no server, network or AI code in the addon (checked by
  a test); the API is documented for scripts, macros and other addons. The
  coding agent's instructions (`CLAUDE.md`) are no longer in the repository.
- Lightweight components: skins are native `Mesh::Feature` objects, displayed
  by a FreeCAD without the addon; the level of detail (box when small on
  screen) is attached at runtime by the addon. Files of 0.1.0 keep working.
- Minimum FreeCAD version: 1.1 (was 1.0).
- Explorer: the "Scan" button is now "Refresh all".
- The version is read from `package.xml` only (`version.py`); the unused
  `VERSION = "1.0"` constants are gone.
